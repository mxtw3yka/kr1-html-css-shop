# Gear

## Описание

Gear — многостраничный каталог электроники и услуг на React и Go. Go-сервер отдаёт 11 товаров через `GET /api/products`; для GitHub Pages Vite включает те же данные в статическую сборку. Форма заявки проверяет данные в браузере, но не отправляет их и не создаёт заказ.

## Структура проекта

- `index.html` — главная страница с подборкой и модальной формой;
- `catalog.html` — каталог с фильтрами и сортировкой;
- `product.html?id=k-200` — карточка товара (у K-200 есть галерея, характеристики и таблица тарифов);
- `order.html` — форма заявки;
- `contacts.html` — контакты и карта;
- `search.html` — поиск по товарам и услугам;
- `cabinet.html` — локальное избранное, без регистрации и синхронизации;
- `src/components/` — общая шапка, футер и карточки товаров;
- `src/pages/` — компоненты страниц;
- `src/data/products.js` — загрузка каталога из Go API, привязка локальных изображений и форматирование цен;
- `backend/data/products.json` — единый источник данных 11 товаров для API и статической сборки;
- `backend/main.go` — Go-сервер API и собранного сайта;
- `backend/cmd/go-demo/` — Go-функции для демонстрации через WebAssembly;
- `src/goDemo.js` — загрузка Go/WebAssembly и команды для консоли;
- `scripts/build-go-demo.mjs` — сборка WebAssembly и копирование Go runtime;
- `src/styles/` — стили интерфейса;
- `images/products/` — локальные фотографии, источники и лицензии в [`CREDITS.md`](images/products/CREDITS.md);
- `lighthouse/` — отчёты Accessibility;
- `public/` — иконка сайта и карта страниц;
- `.github/workflows/pages.yml` — сборка и публикация на GitHub Pages.

## CSS-архитектура

Стили находятся в `src/styles/`: `base.css`, `shell.css`, `pages.css`, `features.css`. Переменные цветов управляют темами; медиазапросы адаптируют навигацию, сетки и формы. При предпочтении уменьшенного движения анимация переключения темы отключается.

## Использование Flexbox и Grid

Flexbox и Grid используются для раскладки шапки, футера, карточек, каталога и форм. В локальном режиме React загружает товары с Go-сервера, затем фильтрует их в браузере; Pages использует статическую копию того же JSON.

## Позиционирование

Шапка и кнопка «Наверх» оформлены стилями оболочки. Кнопка появляется после прокрутки; ссылки на разделы и контакты доступны в навигации.

## Навигация и многостраничная структура

На всех семи страницах есть общие навигация и футер. `product.html` выбирает товар по `?id=`, `order.html` принимает выбор по `?product=`. Без `id` открывается K-200.

## БЭМ-структура проекта

В интерфейсе используются классы с элементами и модификаторами (`shop-gallery__main`, `shop-action--accent`), а общая оболочка вынесена в компонент `Layout`. Это не дословная структура CSS и имён классов из проекта-образца.

## Как посмотреть проект

1. Установите Go (версия указана в `backend/go.mod`) и Node.js 20.19+ или 22.12+.
2. В корне проекта выполните `npm install`.
3. Для разработки в двух терминалах: `cd backend && go run .` (API на `http://localhost:8080/api/products`) и `npm run dev` из корня (адрес покажет Vite; `/api` проксируется на Go).
4. Чтобы Go отдавал готовый сайт с одного адреса: в корне выполните `npm run build`, затем `cd backend && go run .` и откройте `http://localhost:8080/`.
5. Для статической сборки без Go-сервера при просмотре выполните `npm run build:pages`; файлы появятся в `dist/`. Сборка требует установленного Go для WebAssembly.

## Адаптивная вёрстка (практическая работа 12)

Медиазапросы находятся в `src/styles/base.css`, `shell.css`, `pages.css` и `features.css`. На узких экранах меню сворачивается, сетки перестраиваются, форма переходит в одну колонку. Изображения ограничены шириной контейнера и получают `width`/`height`.

| Ширина | Основное изменение |
|---|---|
| до 540 px | одна колонка карточек и полей формы |
| до 760 px | каталог и карточка товара переходят в одну колонку |
| до 1120 px | основная навигация открывается кнопкой меню |
| широкие экраны | многоколоночные сетки товаров и двухколоночная форма |

Для фотографий подготовлены настоящие JPEG-варианты шириной 480 и 1000 px; для миниатюр галереи K-200 — 240 px. `srcSet` и `sizes` позволяют браузеру выбирать файл по размеру блока и плотности экрана. Фотографии товаров ниже первого экрана загружаются лениво.

## Доступность (практическая работа 13)

### Изображения и alt

У содержательных изображений товаров есть описание товара или ракурса. Миниатюры галереи имеют пустой `alt`, потому что их кнопки уже содержат название действия и фотографии. Декоративный значок «Наверх» также имеет пустой `alt`; декоративные SVG скрыты от скринридеров.

### ARIA: только там, где без неё не обойтись

Для структуры используются обычные `header`, `nav`, `main`, `footer`, `label`, `fieldset`, `table`, `caption` и `th scope`. `aria-current` отмечает текущий раздел, `aria-expanded` и `aria-controls` описывают раскрытие меню, `aria-pressed` — состояние избранного и выбранной миниатюры. Иконкам без текстового названия дано доступное имя, а результат проверки формы озвучивается через `role="status"`. Лишние роли на нативных кнопках и ссылках не добавлены.

### Lighthouse

Аудит Accessibility запущен Lighthouse 13.6.0 на локальном сайте. Сохранены [полный HTML-отчёт по главной странице](lighthouse/accessibility-report.html) и JSON-отчёты в `lighthouse/`. После исправлений мобильные аудиты всех семи страниц и десктопные аудиты главной и каталога дали 100/100; повторный мобильный аудит карточки товара после подключения responsive images — также 100/100. Автоматический балл не означает полного соответствия WCAG.

## Проверка адаптивности (практическая работа 14)

Проверены семь страниц на ширинах 360, 430, 768, 1024 и 1440 px (35 комбинаций). Горизонтальной прокрутки документа и полей, выходящих за экран, нет. Таблица характеристик K-200 помещается в контейнер; широкая таблица тарифов на телефоне прокручивается внутри `.shop-table-scroll`, не расширяя страницу. Форма заявки остаётся в одну колонку на телефоне и в две на широком экране. При открытии каталога на телефоне браузер выбирает уменьшенные изображения 480 px; ленивые изображения проверены после прокрутки к ним.

## Go: API товаров и демонстрация WebAssembly (практика №15)

`backend/data/products.json` — общий каталог. `backend/main.go` встраивает его в сервер и отдаёт `GET /api/products` (`application/json`). Обычная сборка React загружает товары через API; Vite перенаправляет запросы `/api` на Go в режиме разработки. Go-сервер также раздаёт готовый `dist/`.

GitHub Pages не запускает серверный Go. `npm run build:pages` включает тот же JSON в статическую сборку — каталог работает без API, но серверного обновления товаров на Pages нет. Для обновления опубликованного каталога нужно пересобрать и развернуть сайт.

Консольная демонстрация собирается из `backend/cmd/go-demo/` в WebAssembly. В браузере откройте DevTools → Console и дождитесь результата Go-функций. Для ручного запуска:

```js
await goDemoReady
goDemo.run()
goDemo.formatPrice(3200)
goDemo.calculateDiscount(3200, 3900)
goDemo.getProductStatus(false)
goDemo.createProductSummary({ title: 'Клавиатура', price: 3200, isAvailable: true })
```

Форматирование цены, размер скидки в рублях, статус и краткое описание вычисляются Go-кодом; JavaScript загружает модуль и показывает результат. Это не отправка заявки и не учётная запись.
